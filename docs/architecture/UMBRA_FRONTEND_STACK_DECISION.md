\# UMBRA FRONTEND STACK DECISION



\# FINAL FRONTEND DIRECTION



Umbra Nexus will use a React-centered operational rendering architecture optimized for:

\- deterministic replay

\- persistent operational state

\- geospatial rendering

\- synchronized multi-panel orchestration

\- high-density operational overlays



\---



\# PRIMARY STACK



\## Frontend Framework



React



\## Language



TypeScript



\## Build System



Vite



\## Styling



Tailwind CSS



\## Component Primitive System



shadcn/ui



\## Animation



Framer Motion (strictly operational use only)



\---



\# WHY REACT



React provides:

\- deterministic component state

\- mature ecosystem

\- map ecosystem compatibility

\- replay-safe state orchestration

\- scalable operational shell architecture



React also integrates cleanly with:

\- MapLibre

\- deck.gl

\- Zustand

\- WebSocket event streams

\- geospatial rendering pipelines



\---



\# WHY TYPESCRIPT



Type safety is mandatory for:

\- replay integrity

\- operational synchronization

\- entity lineage

\- convergence systems

\- event bus stability



Untyped operational state is prohibited.



\---



\# WHY VITE



Vite provides:

\- rapid iteration

\- deterministic builds

\- modern module architecture

\- scalable frontend tooling



\---



\# WHY TAILWIND



Tailwind supports:

\- operational UI density

\- deterministic styling

\- rapid shell iteration

\- controlled visual systems



Decorative component frameworks are prohibited.



\---



\# WHY SHADCN/UI



shadcn/ui supports:

\- composable primitives

\- operational styling control

\- deterministic UI construction

\- low abstraction overhead



\---



\# FRONTEND ARCHITECTURE MODEL



Umbra frontend architecture is:



Map-first.



Not page-first.



The persistent shell remains mounted while:

\- layers change

\- replay changes

\- simulations branch

\- overlays synchronize



\---



\# PROHIBITED FRONTEND PATTERNS



Prohibited:

\- page reload state destruction

\- dashboard routing paradigms

\- disconnected widgets

\- opaque local component state

\- hidden synchronization logic



\---



\# RENDERING PHILOSOPHY



Rendering priority:

1\. operational clarity

2\. replay integrity

3\. provenance visibility

4\. synchronization stability

5\. rendering performance



\---



\# FUTURE SUPPORT



Frontend architecture should support:

\- multi-monitor operational surfaces

\- collaborative operational sessions

\- distributed replay rooms

\- large-scale simulation orchestration

\- AI-assisted analysis surfaces



\---



\# FINAL DECISION



Approved stack:

\- React

\- Vite
