\# UMBRA VISUAL RENDERING CONTRACT



\# VISUAL PHILOSOPHY



Umbra Nexus is an intelligence operating environment.



Visuals must communicate:

\- operational truth

\- confidence

\- provenance

\- convergence

\- temporal state

\- simulation state

\- replay state



Visuals must never prioritize aesthetics over explainability.



\---



\# PRIMARY VISUAL PRIORITY



\## Priority Order



1\. Operational clarity

2\. Spatial coherence

3\. Provenance visibility

4\. Temporal readability

5\. Convergence explainability

6\. Simulation differentiation

7\. Performance stability

8\. Visual aesthetics



\---



\# MAP-FIRST RENDERING MODEL



\## Core Rule



The map is the primary rendering surface.



Everything else supports interpretation of map state.



\---



\# VISUAL HIERARCHY



\## Tier 01 — Canonical Truth



Examples:

\- authoritative boundaries

\- validated infrastructure

\- replay-verified entities

\- canonical geometry



\## Rendering Rules



Highest stability.



Strongest visibility.



Minimal animation.



\---



\## Tier 02 — Operational Signals



Examples:

\- live events

\- alerts

\- entity movement

\- ingestion status

\- anomaly indicators



\## Rendering Rules



Dynamic but explainable.



Must never obscure canonical truth.



\---



\## Tier 03 — Predictive / Simulation Layers



Examples:

\- forecasts

\- branch scenarios

\- convergence projections

\- hypothetical overlays



\## Rendering Rules



Must remain visually distinct from canonical truth.



Never visually indistinguishable from validated reality.



\---



\# COLOR SYSTEM RULES



\## Canonical Truth



Stable neutral palette.



\## Alerts / Failures



Reserved high-contrast palette.



\## Simulation States



Distinct but muted.



\## Replay States



Temporal gradient-based.



\## Provenance Confidence



Opacity and intensity linked to confidence score.



\---



\# MOTION RULES



\## Allowed Motion



\- camera transitions

\- timeline playback

\- replay progression

\- event pulse indicators

\- controlled layer fades



\## Prohibited Motion



\- decorative animation

\- continuous idle motion

\- non-informational movement

\- attention-hijacking effects



\---



\# PROVENANCE VISUALIZATION



\## Rules



Every rendered entity must visually expose:

\- confidence

\- source integrity

\- replay verification status

\- mutation history



Possible mechanisms:

\- outline styles

\- opacity

\- edge glow

\- provenance badges

\- hash-linked inspectors



\---



\# TEMPORAL VISUALIZATION



\## Rules



Time must be visually legible.



The interface must support:

\- historical reconstruction

\- replay progression

\- branch divergence

\- convergence evolution



Temporal changes must never appear random.



\---



\# CONVERGENCE VISUALIZATION



\## Rules



Convergence scoring must remain explainable.



Possible mechanisms:

\- layered heatmaps

\- signal overlap zones

\- confidence contours

\- weighted overlays



No black-box heat rendering.



\---



\# FAILURE VISIBILITY



\## Rules



Failures must remain visible.



Examples:

\- topology mismatch

\- replay divergence

\- missing provenance

\- stale ingestion

\- validation failure



Failures must never silently disappear.



\---



\# DENSITY MANAGEMENT



\## Rules



The interface must support:

\- city scale

\- regional scale

\- national scale

\- global scale



Density reduction must preserve:

\- provenance

\- explainability

\- replay consistency



\---



\# MAP LAYER RULES



\## Canonical Layers



Always replay-safe.



\## Dynamic Layers



Must expose update cadence.



\## Simulation Layers



Must remain isolated from canonical truth.



\## Experimental Layers



Must be visually flagged.



\---



\# INSPECTOR VISUAL RULES



\## Rules



Inspectors must prioritize:

1\. provenance

2\. replay status

3\. temporal history

4\. convergence explanation

5\. source integrity



before:

\- decorative visuals

\- charts

\- analytics summaries



\---



\# REPLAY VISUALIZATION



\## Rules



Replay must visibly communicate:

\- current replay tick

\- branch origin

\- mutation chain

\- validation status

\- deterministic state restoration



\---



\# PERFORMANCE RULES



\## Rules



Performance optimization must never:

\- alter canonical truth

\- skip provenance checks

\- mutate geometry

\- bypass replay validation



Visual degradation is preferable to integrity loss.



\---



\# UI AESTHETIC TARGET



Umbra Nexus should visually resemble:

\- advanced geospatial intelligence systems

\- operational command environments

\- simulation platforms

\- infrastructure monitoring systems



Umbra Nexus should not resemble:

\- consumer dashboards

\- business KPI panels

\- marketing analytics software

\- generic admin systems



\---



\# FINAL VISUAL GUARANTEE



Every visual state in Umbra Nexus must be:

\- explainable

\- replayable

\- provenance-linked

\- deterministic

\- operationally meaningful
